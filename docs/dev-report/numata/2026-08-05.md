## 1. やったこと

### 1.1 開発規約を実態に合わせて修正した（8/4）

規約の記載とリポジトリの実態が食い違っている箇所を2つ是正した。

**ブランチ運用（§6）**

規約は「原則として `develop` ブランチは使用しない」だったが、実際は `develop` が既定ブランチで、
全コミットがそこに載り、`main` は初期コミットのまま放置されていた。実態に合わせて3層構成を正式採用した。

| ブランチ | 役割 | 分岐元 | マージ先 |
| --- | --- | --- | --- |
| `main` | 本番環境へ反映するコードを管理 | — | — |
| `develop` | 各メンバーの作業内容を集約。既定ブランチ | `main` | `main` |
| 作業ブランチ | 各機能や修正を実装 | `develop` | `develop` |

`main` への直接pushの禁止に加え、`develop` も禁止に拡張。§6.4 の作業開始手順、§8.1・§22・§23・§24・§26-2 の
`main` 参照も役割ごとに振り分けた。

**フレームワーク（§2）**

規約の「バックエンド: Next.js」に対し、実態は React Router v7（フレームワークモード・SSR有効）。
代表に確認したところ **Next.js への移行はカンパニー全体の意向**とのことだったため、
「MVPまでは React Router v7、公開後に移行」として [ADR 0002](../../decisions/0002-framework-react-router.md) に記録した。
ADRには移行時に影響する箇所の一覧も残した。

### 1.2 サークル情報に実データを入れた（8/4）

フォーム回答から同期済みだった8団体について、詳細ページを実データで表示できる状態にした。

| 対応 | 内容 |
| --- | --- |
| データ記入 | 8団体に `genres` / `summary` / `recommendedFor` / `isOfficial` / `isRecommended` を記入 |
| サンプル削除 | モックデータ5件（`sample-*`）と、対応する埋め込みエントリを削除 |
| 表示の不具合修正 | 紹介文・実績の改行がつぶれていた（`whitespace-pre-line` を追加）。実績の年が空のとき空行ができていた |
| バッジ追加 | 型にあるのに未描画だった `isOfficial` を「公認」バッジとして表示 |

**画像は表示できないことが判明した。** フォーム回答の画像はGoogle Driveの共有リンクだが、
**ファイルが非公開**でサインイン画面のHTMLが返る。`uc?export=view` や `thumbnail` 形式でも同じだった。

さらに `images` / `logo` は `scripts/sync-circles.ts` の所有フィールドで、
`app/data/circle-info/circles.ts` を直接書き換えても次回の同期で上書きされる。

そのため表示層で解決する形にした。

- `app/services/circle-info/image-overrides.ts`（新規）… 手動配置した画像パスの登録表。同期スクリプトが触らない場所で管理する
- `circle-service.ts` … 読み出し時にパスを差し替え、描画できないDrive URLを除外する。除外後はプレースホルダにフォールバックするため画像切れが出ない
- `public/circles/README.md` … ダウンロードと配置の手順

### 1.4 開発サーバーが起動しなくなる不具合を2件直した（8/4）

| 事象 | 原因 | 対応 |
| --- | --- | --- |
| `@supabase/supabase-js` が見つからない | チャットボット機能のマージで依存が増えたのに `npm install` が未実行だった | `npm install`。ブランチ切り替え後の実行を習慣化する |
| 「探す」ページへ遷移できない | **サービスワーカーのキャッシュ**。`sw.js` がページ遷移以外をすべて Cache-First で処理しており、React Router の `.data` リクエストとモジュールJSが古いまま返っていた | 下記 |

サービスワーカーの件は、`CACHE_NAME` が `v1` 固定で更新されない設計だったため、
**放置すると本番でも「デプロイしてもユーザーに古いJSが配られ続ける」事故になる**状態だった。

- 開発中はサービスワーカーを登録しない（`import.meta.env.DEV` で分岐）。既存の登録も自動で解除する
- `CACHE_NAME` を `v2` に更新し、`activate` 時に旧キャッシュを一掃
- `.data` リクエストと GET 以外を対象外に。Cache-First は `/assets/` `/icons/` などハッシュ付きのものだけに限定
  （GET以外は `cache.put` が例外を投げる潜在バグもあった）

### 1.5 プロジェクト構成を整理した（8/5）

ファイルが98個まで増え、`services` に21ファイルが平場で並ぶなど、
どのファイルがどの機能のものか名前でしか判別できない状態だったため整理した。
[ADR 0001](../../decisions/0001-folder-structure.md) が「ページ数が増えた段階で再検討」として保留していた論点。

**各層の中を機能名のディレクトリで分けた**（`components/features/<機能>/` と粒度が揃う）。

```
app/services/  circle-info/ chatbot/ news/
app/data/      circle-info/ chatbot/ news/ faq/
app/types/     circle-info/ chatbot/ news/
app/lib/       circle-info/ chatbot/
```

チャットボット関連は担当外のため、**内容は一切変更せず移動と import の追随のみ**とした。

`scripts/` の生成スクリプトが「出力先パス」と「生成するファイルに書き込む import 文」を
文字列で持っていたため、両方を追随させた。片方だけだと次回実行時に壊れたファイルが書き出される。

**ドキュメントも整理した。**

- アプリ全体の方針（規約・アーキテクチャ・全体要件）を `docs/project/` に
- チャットボットの2ファイルを `docs/chatbot/` に（`circle-info/` と同じ `overview.md` / `spec.md` の命名に）
- 紛らわしかったファイル名を変更（`design-requirements.md` → `design-guidelines-input.md`、
  `requirements.md` → `product-requirements.md`、`hearing_point.md` → `hearing-points.md`）

### 1.6 サークル情報のスタイルをCSS Modulesへ分離した（8/5）

`app/components/features/circle-info/` の10コンポーネントについて、
JSXに直書きしていたTailwindのユーティリティクラスを `*.module.css` へ移した。

- 色・角丸・影は `app/styles/app.css` の `@theme` を `var()` で参照し、デザイントークンを二重に持たない
- 詳細カード3種で共通する枠・見出しは `detail/detail-card.module.css` に切り出し、`composes` で取り込む

要件定義書 §15-2 は CSS Modules を指定していたが、デザイン規約 §26.3 は「例外時のみ」としており、
[hearing-points.md](../../project/hearing-points.md) §2 が未決のままだった。
今回これを CSS Modules 側で確定させ、[ADR 0003](../../decisions/0003-css-modules-and-feature-directories.md) に記録した。

規約側も更新した。

- デザイン規約 §26 を CSS Modules 前提に改訂
- §26.5 を新設し、`hover` の `@media (hover: hover)`、`ring-offset` の二重 `box-shadow`、
  透明度の `color-mix` など、移行時に挙動が変わる箇所を明記
- 開発規約 §12.2（機能単位でまとめる）を新設
- **どちらも全体適用は 2026/08/06 以降**とし、それまでは各担当者の進め方を優先する旨を明記
