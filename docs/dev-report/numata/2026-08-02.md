## 1. 今日やったこと

### 1.1 サークル情報機能の設計方針を決めた

「機能ごとに小さなアプリとして開発し、がんちゃんねるに統合する」という進め方に対して、
既存の層構成（ADR 0001）に沿って `routes` / `components/features` / `services` / `types` / `data` に
分散配置する方針を採用した。機能単位で1ディレクトリに固める案は、ADRの変更が必要になるため
ページ数が増えた段階で再検討することにした。

あわせて機能単位のドキュメント置き場として `docs/circle-info/` を新設し、
「機能単位の要件・仕様は `<機能名>/` にまとめる（ディレクトリ名はURL slugと揃える）」という
運用ルールを `docs/README.md` に追記した。

### 1.2 要件定義と仕様書を作成した

仕様を詰めるためのインプット記入シート（`input-sheet.md`）を用意して記入し、
その内容と画面イメージ3点をもとに要件定義書・仕様書を作成した。

**記入内容から整理した主なポイント**

| 論点 | 整理結果 |
| --- | --- |
| 分類 | **2軸**に分けた。団体種別（部活/サークル/同好会/学内カンパニー/学生委員会/NEXT STEP工房/その他）× ジャンル（運動系/文化系/音楽系/学術系/ボランティア/その他、複数可）＋自由タグ＋募集ステータス |
| 必須項目 | 団体名のみ。それ以外はすべて任意 |
| 未入力の扱い | 「未登録」を並べない。項目が空なら行ごと、セクション全体が空ならセクションごと非表示 |
| データの持ち方 | MVPは `app/data/circles.ts` の静的データ。30〜50団体の規模ではAPI新設のコストに見合わない |

**確定した決定事項**

| # | 論点 | 決定 |
| --- | --- | --- |
| 1 | お気に入りをMVPに入れるか | 入れる。`localStorage` 版（ログイン不要）で実装 |
| 2 | 共通フッターとの共存 | `/circle-info` 配下では共通ナビを機能内ナビに差し替える |
| 3 | 「探す」の絞り込み軸 | ジャンルのみ。団体種別は詳細画面のバッジ表示に使う |
| 4 | カラートークン | 実装前に `app/styles/app.css` の `@theme` に定義する |

### 1.3 デザイントークンを整備した

デザイン規約 §26.2 に定義済みだったカラートークン（色12種・角丸3種・影2種）を
`app/styles/app.css` の `@theme` に反映した。これまで規約上は `bg-primary` などの指定が必須なのに
トークンが未定義で、規約準拠のコードが書けない状態だった。

あわせて是正リスト（規約 §29）の優先度「高」のうち3件を対応した。

- `<html lang="en">` → `lang="ja"`
- フォントを `Inter`（ラテン専用）→ `Noto Sans JP` 400/700 に差し替え
- `dark:bg-gray-950` の中途半端なダークモード対応を削除

### 1.4 サークル情報の3画面を実装した

画面イメージに沿って、ホーム・探す・詳細を実装した。お気に入り（気になる）も
画面イメージ上は全カードにハートがあるため、`localStorage` 版として合わせて実装した。

| 画面 | URL | 内容 |
| --- | --- | --- |
| 共通レイアウト | — | ヘッダー＋ボトムナビ。md:以上では上部ナビに切り替え |
| ホーム | `/circle-info` | 紹介バナー・「サークルを探す」ボタン・おすすめの2列グリッド |
| 探す | `/circle-info/search` | キーワード／ジャンル／タグの3条件（AND）、件数表示、0件時の空状態 |
| 詳細 | `/circle-info/:circleId` | ヒーロー画像・バッジ3種・こんな人におすすめ・タグ・情報カード4種・SNS/連絡先 |
| 気になる | `/circle-info/favorites` | 保存した団体の一覧 |

### 1.5 アプリ全体のナビゲーションを整備した

サークル情報側の作りに合わせて、アプリ全体側も揃えた。

- **下部固定ナビを刷新** — 共通コンポーネント化して、アプリ全体と機能内で同じ部品を使い回す形にした。
  項目は左からホーム／機能一覧／Q&A／設定。高さ96px→64px、アイコン40px→24px、文字ラベル併記、
  `aria-current` 付与（規約 §19.2）。グローバルCSSだった `footer.css` は廃止した
- **共通ヘッダーを新設** — アプリアイコン＋「がんちゃんねる」＋ハンバーガー。
  パスなしレイアウトルート `_app.tsx` を作り、ホーム・機能一覧・Q&A・設定の4ページに適用した
- **機能一覧ページを新設** — ニュース・Q&A・サークル情報を2列グリッドのカードで表示
- **設定ページを新設** — ナビからの導線を通すためのプレースホルダ

### 1.6 不具合を修正した

| 事象 | 原因 | 対応 |
| --- | --- | --- |
| 広告バナーがナビに重なる | ナビは `h-16`＋`border-t` で計65pxだが、広告が `bottom-16`（64px）に配置されていた | `bottom-20`（80px）に変更 |
| 広告の「問い合わせはこちらから」がはみ出す | 箱が `h-22`（88px）固定なのに、中身が約105pxあった | 高さ固定を解除し、中身に合わせて伸びるようにした。下余白も `pb-48` に拡大 |
| スクロールすると広告が消える | 下スクロールで `invisible` を付けるスクロール監視が入っていた | `useState`×2 と `useEffect` を削除し、常時表示に変更 |
| 詳細ページに `<h1>` が2つ | 共通ヘッダーのタイトルと団体名が両方 `h1` だった | ヘッダー側を `<p>` に変更し、見出しは各画面が持つ形に統一（規約 §24.1） |
| フッターのサークルタブが404 | 存在しないパス `/circle` を指していた | `/circle-info` に修正 |
