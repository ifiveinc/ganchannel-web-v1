# サークル情報（circle-info）要件定義

- ステータス: **レビュー待ち**
- 最終更新: 2026-08-02
- インプット: [input-sheet.md](./input-sheet.md)（記入済み）、[images/](./images/)（画面イメージ3点）

---

## 1. 背景・目的

岩手大学の学生が、サークル・部活・学内カンパニーなどの学生団体を探すとき、
情報が各団体のSNSやチラシに散らばっており、一覧して比較することができない。

がんちゃんねる内に、学内の団体情報を集約して探せる機能を用意する。

**この機能が目指す状態**

「この機能を使って自分に合うサークルを見つけられた」という声が上がること。

**参考サービス**

- 慶應義塾大学 公認サークル紹介サイト — https://orientation.keio-zenkyo.net/circle2026/17
- 東洋大学 サークル紹介 — https://sites.google.com/toyo.jp/student-support/circle/list

## 2. 想定ユーザー

| ユーザー | 利用場面 | この機能で解決すること |
| --- | --- | --- |
| **新入生** | 入学直後、サークルや学内カンパニーを探すとき | 学内にどんな団体があるかを一覧で把握できる |
| **在学生** | 運動系を探すとき／新しくできた趣味の団体を知りたいとき／学内カンパニー等の学生向けプログラムに参加したいとき | 目的（ジャンル・雰囲気）から団体を絞り込める |
| **団体運営側** | 団体を立ち上げたとき／サークルオリエンテーション・文化祭・オープンキャンパスで人を募集したいとき | 掲載を通じて新入生・在学生に認知される |

**ユーザーが満たされる条件（優先順）**

1. 探したい団体を見つけられる
2. 見つけた団体の情報を知れる
3. 機能全体が使いやすい

| 内容 | 想定時期 |
| --- | --- |
| ログイン機能 | 年内 |
| お気に入りのアカウント同期（端末間の同期） | ログイン導入とあわせて |
| 団体運営側による情報編集画面 | 未定 |

| FR-02 | 団体の詳細情報を閲覧できる | P0 |
| FR-03 | キーワードで検索できる（団体名・紹介文・タグを対象） | P0 |
| FR-04 | ジャンルで絞り込める | P0 |
| FR-05 | タグで絞り込める（「ガチ」「エンジョイ」等の自由キーワード） | P0 |

## 5. 非機能要件

| 項目 | 要件 |
| --- | --- |
| 対応端末 | **スマートフォン中心**。PCでも破綻しないこと |
| 掲載団体数 | MVP時点 10〜15団体 → 最終的に 30〜50団体 |
| 表示速度 | 上記件数では全件をクライアントに渡して問題ない規模。ページングは不要 |
| デザイン | [../design-guidelines.md](../design-guidelines.md) に準拠 |
| アクセシビリティ | 同上（コントラスト確保、タップ領域の確保） |
| SEO | MVPでは考慮しない |

## 6. データ

### 6.1 収集・更新の体制

| 項目 | 内容 |
| --- | --- |
| 収集方法 | 団体側にフォームから登録してもらう＋大学・学生団体からデータを提供してもらう |
| 更新担当 | iFiveメンバー |
| 更新頻度 | **未定**（§8-2 の未決事項） |
| 掲載許諾 | フォーム記入時に同意を確認する |

### 6.2 掲載する情報

**必須はサークル名のみ。それ以外はすべて任意**（未入力があっても掲載できる）。

| 分類 | 項目 |
| --- | --- |
| 基本 | 団体名、団体種別、ジャンル、タグ、募集ステータス、短い紹介文、詳しい紹介文、こんな人におすすめ |
| 活動情報 | 活動場所、活動日時・頻度、募集期間 |
| 費用 | 入会費、年会費、その他費用 |
| メンバー構成 | 総人数、男女比、初心者割合 |
| 実績 | 年ごとの活動内容 |
| 連絡先 | 代表者名、連絡先、Instagram、X、公式サイト |
| その他 | 対象学部・学年の制限、新歓イベント日程、公認/非公認の区分、写真（ロゴ・活動風景） |

> 任意項目が未入力の場合の表示ルールは [spec.md](./spec.md) §3-3 で定義する。

### 6.3 分類

記入シートの回答と画面イメージから、**分類は2軸**あると整理した。

| 軸 | 値 | 選択数 | 用途 |
| --- | --- | --- | --- |
| **団体種別** | 部活 / サークル / 同好会 / 学内カンパニー / 学生委員会 / NEXT STEP工房 / その他学生有志団体 | 1つ | 詳細画面のバッジ表示 |
| **ジャンル** | 運動系 / 文化系 / 音楽系 / 学術系 / ボランティア / その他 | 複数可 | 「探す」画面での絞り込み・カードのバッジ |

加えて、フォームで入力してもらう**自由タグ**（「ガチ」「エンジョイ」「初心者歓迎」「週1以下」等）と、
**募集ステータス**（募集中 / 募集停止）を持つ。

「探す」画面の絞り込みに使うのは**ジャンルのみ**とする（2026-08-02 決定）。団体種別は詳細画面の
バッジ表示に使う。

> ジャンルの値は画面イメージから読み取った暫定案。§8-2 の未決事項。

## 7. 将来機能の方針（Q6-2への回答）

MVPで作る範囲（§7-1）と、MVP後に作る範囲の方針を示す。
MVP後の機能は、**MVPの実装がそれらの妨げにならないように**設計する。

### 7.1 お気に入り（気になる）— **MVPに含める**（2026-08-02 決定）

ログインを待たず、`localStorage` に団体IDの配列を保存する方式で実装する。

- 保存するのは団体IDの配列だけなので、サーバもログインも不要
- 実装コストは小さく、UIを画面イメージ通りに保てる
- ログイン導入後は「端末内のIDリストをアカウントに紐付けて移行する」だけで済む
- **制約:** 端末をまたいだ同期はできない。ログイン導入時に解消する

### 7.2 ログイン（年内）

- データ取得を必ず `services/` 経由にしておけば、認証付きAPIへの差し替えが局所的に済む
- 学生限定にするなら大学メールドメインでの検証が必要。認証方式の選定は別途

### 7.3 団体運営側の編集権限

- 本格的な管理画面は認証・権限・監査が必要でコストが大きい
- **当面はフォーム（Google Forms等）での更新依頼を受け、iFive側が反映する運用を推奨**
- 将来的には、団体ごとに発行した編集用トークンで該当団体のみ編集可能にする方式が現実的

### 7.4 リコメンド

- 30〜50団体の規模では機械学習は不要
- **タグの一致数によるルールベース**で十分機能する
- 閲覧履歴を `localStorage` に貯めれば、ログイン前でも「よく見ているタグ」からの推薦が可能
